# Changelog

## 2.57.0

- `citt capture-start --set-pref FILE.xml:KEY=TYPE:VALUE` (TASK-1596, NP-2080, feedback 67): before the app starts in each session, VALUE is written under KEY into the app's SharedPreferences file `FILE.xml` on the Android lab phone, so a run can start an app with a stored flag already set (a paid-user flag, a finished onboarding, a consent choice). TYPE is `bool`, `int`, `long`, `float` or `string`; the option is repeatable, at most 20 entries in at most 5 files; `{package}` in FILE is the app's package id. You name the file and the key the app reads (`citt code-search`, `citt code-file`). The start line adds `; app preferences set before launch (N keys in M files)`, `citt captures` states `app preferences set`, each `citt capture-watch` session line states the keys and files written, `read back verified` or `not verified`, and the keys kept at the end of the session with both values of a changed key, and `citt capture-options` has the line `App preferences (--set-pref): available`. The record of each session is in `run.json` under `sessions[].persona.set_prefs` (`verified`, `existed`, `previous`, `after_session`, `files_after`). Limits: plain SharedPreferences XML only; an EncryptedSharedPreferences file and a Jetpack DataStore file are refused with the reason; string sets and iOS apps are not available; a key that contains `=` and a file name that contains `:` cannot be given through the option.
- `citt captures` has a `Stuck` column after `Sessions` (NP-2073, feedback 62): the number of the run's sessions that were held on one screen with the kind of screen, such as `2 age question` or `1 consent wall`, a dash for none. `--json` has `stuck_sessions` and `stuck_on` on every run, the two fields a queue reads to stop booking an app whose sessions end on the same screen. `citt capture-watch` ends such a run with one sentence that names the screen and states that the app's traffic past it is not in these sessions. The run state and the exit codes are unchanged.
- `citt capture-options` prints one line per US exit state whose NordVPN servers ipinfo.io places in another state (NP-2078, feedback 62), such as `Exit state OR: NordVPN's OR servers are placed in California by ipinfo.io (28 of 28 connects in the last 7 days). ...`; `--json` has `region_note` and `reading` on each state. `citt capture-watch` prints `  exit: OR booked, ipinfo region California` before the line of a session that was recorded with another region than the booked state. The `--state` line of `citt capture-start --help` states that a run is captured on a NordVPN server of the booked state and that the session records the region ipinfo.io reads.
- `citt task ID`: the part of an app that waits for its build states the step and the number of jobs ahead in the NOTE column (TASK-1581, feedback 63), such as `In the download queue, 3 ahead; 2 accounts take turns` or `Decompiling`. The text is the service's `parts[].detail`; the docs and `commands/task.md` state it.
- `citt campaign show` prints what the campaign's planning did (TASK-1592, feedback 64 and 66), after the `Apps:` line: `Planning: last plan call <time> booked 2 runs.` or `booked nothing: "<reason>"` with the model's reason, `Plan calls: 142, 44 without a booking, 3 since the last booking at <time>.`, `Waiting: 11 ready apps with no run, 4 booked ahead, 435 not pulled yet.` with the sentence that states when the next apps are pulled, and the next plan call of a running campaign. `Attention: ...` is the second line when the last plan calls booked nothing while a phone was free. `Phone time while running: ... h in campaign runs, ... h idle (4.8 %), ... h on other work, ... h not usable; last hour: 12.5 % idle. Measured from <time>.` follows the device hours, and `Idle phones:` is now `Idle phones now:`. `citt campaign pause` prints that a paused campaign keeps its slot; `citt campaign resume` of it prints `running` at once, and a campaign that waits prints `queued, place N of Q in the queue (M campaigns run at once)`. `--json` of `show`, `pause` and `resume` has the blocks `planning`, `phone_time` and `queue`. The docs state that `stop` frees the slot, that a campaign that ended as finished with apps left is started again with `citt campaign resume`, and what `booked ahead` and `not pulled yet` count. Limits: the planning lines appear from the campaign's next plan call after the update, and the phone time from the hour of the update.
- `citt campaign` takes arms (TASK-1601, feedback 68): one campaign compares several setups of the same apps, such as install referrers. `citt campaign draft --arm NAME[=REFERRER]` (repeatable) and `--arms-file FILE` write the spec key `arms`: `--arm NAME` is an arm without a referrer (the control arm, whose runs install the stored build) and `--arm NAME=REFERRER` an arm whose runs install the app from the Play Store with that install referrer, the decoded value of a Play link's `referrer` parameter. The campaign books every arm of every app; 4 apps and 5 arms are one campaign of 20 runs or more. `draft` exits 2 with the next step for a name outside 1 to 40 letters, digits, underscore, dot and hyphen, a name given twice, an empty referrer, a link as the referrer, more than 20 arms, a referrer arm beside `--platform ios`, and `--template install_referrer=...` (use `--arm`). `citt campaign check` prints `Arms: N (names); runs: R or more; device hours needed: H of A available` and a `hint:` line when the arms need more device hours than the phones have before the deadline. `citt campaign edit ID --arm NAME[=REFERRER]` adds an arm and `--remove-arm NAME` takes one out. `citt campaign show` lists the arms with their referrers, wave and run lines name their arms in `show --app` and `watch`, and `citt campaign report` prints the table `PACKAGE  ARM  RUNS  ENDED  ADS  HITS  VERDICT` with one row per app and arm after the Markdown report; `--json` has `report.arm_matrix` and `arm` on each run, and each `run.json` of `citt campaign pull` has `run.campaign` with `arm`. Against a service without arms the refusal is followed by `hint: this service does not take arms yet`. Limits: at most 20 arms; a referrer arm runs Android apps only and installs the version the Play Store serves that day; the setup of an arm name stays the same for the whole campaign. A campaign without arms prints what it printed before.
- `citt campaign draft --apps-file FILE` takes Play links with a `referrer` parameter as lines (TASK-1602, feedback 68), one install referrer per app, and `--arm NAME=@app` writes the arm whose runs use each app's own referrer. An `--apps` value with a link exits 2 with the next step (links go in a file, one per line), and a link beside `--platform ios` exits 2. `citt campaign check` prints `Apps with their own install referrer: n of m`, and for a spec with app referrers and no arms `hint: every run uses its app's referrer and the campaign has no control arm; add arms to compare`.
- `citt campaign draft --set-pref FILE.xml:KEY=TYPE:VALUE` (TASK-1597, feedback 67 and 68) writes `template.set_prefs`, the app preferences of every run of the campaign, with the form of `citt capture-start --set-pref`; beside `--template set_prefs=LIST` it exits 2. The docs describe the three places of `set_prefs` in a campaign spec (the template, an arm, an app with the arm key `app_set_prefs`), with a worked example; the lists of an arm and of an app are written in the spec file.
- The docs state the age screen record of a session (NP-2071, feedback 62): `summary.json` `age_gate`, the `autoplay.jsonl` event `age_gate_stuck` and the navigator row reason `age_confirm_held`.

## 2.55.0

- `citt code-search` and `citt code-file`: fixes from the acceptance run of 2026-11-25 (TASK-1508, epic TASK-1500).
- Case mode: the procedure for agents searches without `--case-sensitive` first (the match then ignores case, so `caramelads` also finds `s4eCaramelAds`; with the flag that search listed 11 apps of 17). `--case-sensitive` is for a search that stops at the time limit, and it misses the other casings of the string. With the flag the matches line names the mode: `matches: N (exact, case-sensitive)`.
- A lower bound of 0 is printed as `matches: none found so far` and `apps: none found so far` (before: `at least 0`); `0 (exact)` stays the line of a string that is absent. The `--json` body is unchanged.
- `--all` and `--out` stop after 3 requests in a row with no row, the same cursor, the same numbers and the same number of files read (4 requests with `--apps`; before: 4 requests, and the files read were not compared, so a scan that moved with no new app could be stopped), exit 12, and print no `next:` line (before: the same command with `--cursor`, which ended the same way). The progress line of each page has the matches found so far: `page N fetched, R rows so far, at least M matches found`.
- After a stop at the time limit the `hint:` line has the number of files the query has to read when the service sent it: `this query has to read about N files; a longer or rarer string reads fewer (--count shows the number), or limit it with --package or --corpus`.
- The `complete:` line of a time stop has the limit that applied: `complete: no (the search stopped at its 30 s time limit before every candidate file was scanned)`. The docs state the limits: 30 s per request without `--time-limit-ms`, at most 90 s on the service, and that the limit is a ceiling.
- New flag `--append` (with `--out`): the rows are added to the end of the file under its header line. The `next:` command of `--out FILE.csv` writes `FILE.next.csv`, and the `next:` command of that run adds to `FILE.next.csv` with `--append` (before: `FILE.next.next.csv`). A run with no row prints `no row written to FILE.csv (the file has its header line only)` (before: `0 apps written to FILE.csv`). After a stop of an `--append` run that no cursor continues, no `next:` line is printed (the command from the first page would add the rows again) and the `hint:` line says so.
- A complete search with no match under `--package`, `--build-id`, `--corpus` or `--path` prints `no code matches "QUERY" in the apps and paths of this search`, and its `hint:` line has only what applies: no `--regex` suggestion when `--regex` is on, and only the flags of the command in the list to drop, `--path` and `--case-sensitive` included.
- `citt code-file --lines A-B` of a part of a file prints `complete: yes (the requested lines)` and, when lines follow, `next:` with the command of the following range (before: `complete: yes` and no command). The line `atlas data as of <time>` is printed when the answer has the time.
- `SKILL.md`: the `citt code-search` entry is in labelled parts (what it is, procedure, flags, footer lines, a table of the exit 12 cases, time limit, limits, refusals, `--json`), with pointers to `--count` or `--apps` for the exact number of one app, to `--all` for pages with no `--cursor` value copied by hand, and to a search of a behaviour word with `--path 'pkg/path/**'` when the name of an SDK matches mostly import lines.

## 2.54.0

- `citt code-search --context N` (TASK-1506, epic TASK-1500 phase 2): N lines (0 to 10) before and after each matching line, printed in grep style: `PACKAGE  PATH:LINE: TEXT` for the match, `PACKAGE  PATH-LINE- TEXT` for a context line, `--` between two matches. With `--out` the CSV has the columns `context_before` and `context_after` (the lines of a cell joined by a newline). `--context` applies to line rows, not to `--apps` or `--count`.
- `citt code-search --path GLOB` (repeatable, at most 16): only files whose path matches a glob; `*` is any run of characters except `/`, `**` any run, `?` one character except `/`; a glob with no `/` is compared with the file name. It works with `--apps` and `--count`.
- New command `citt code-file PACKAGE PATH [--lines A-B] [--build-id ID] [--corpus C] [--json] [--out FILE]`: the lines of a file of an indexed app build with their line numbers, then `file: PATH (build ID), lines A-B of T`, `complete: yes` or `complete: no (<reason>)`, and `next:` with the command of the range that follows when the answer was cut at the size limit of one request. `--out FILE` writes the lines without numbers and follows the ranges to the end. An unknown file prints the reason and the search that lists the paths of the app (exit 4).
- Paging to the end: against a service that pages by position, `--all` and `--out` follow the pages to `complete: yes` with no row cap of one search; a full page that is not the last prints `complete: no (more rows follow on the next page)` and the command of the next page. `--max-rows` stays the bound of the plugin with its default, and `--max-rows 0` is no bound (before: a usage error). A page can have no row and a cursor (the search read files with no match, or the app list of `--apps` is not ready: its rows are listed by the call that ends the scan, and the calls before it have one cursor and numbers that grow); a single page prints the lower bounds, `complete: no` and the `next:` command, and a walk follows the cursor. A walk stops after 3 requests in a row with no row, the same cursor and the same numbers (exit 12), or after `--max-empty-pages N` pages in a row with no row (new flag, default 50, 0 is no bound, exit 0); `next:` is the command that continues at that page.
- A server without context lines, the path filter or the file read prints the message of the service and a next action (for `--context` and `--path` the same command without the flag), exit 8. `--context` against a server that returns no context lines prints that and exits 10.
- The footer of `citt code-search` changed: a line that starts with `next:` is a command to run as printed, and a sentence (how to narrow, what to check) is on a line that starts with `hint:`. The `or:` line of the footer is gone: after a stop at the time limit the command with the longest time limit of the service is the `next:` line (before: `or:`) and the narrowing sentence the `hint:` line (before: `next:`); the same for a stop at `--max-rows`, and the sentence of a search with no match is a `hint:` line. A search that made no progress inside its time limit prints the sentence of the service as `hint:` and a command with a longer time limit only when the service names one. With `--json` the two lines are on stderr.
- `--apps --out`: the CSV has one more column at the end, `builds_exact` (`true`, `false` for a builds number that is a lower bound, empty when the service has no such field). An app with no sample line prints `-` in the columns SAMPLE PATH:LINE and SNIPPET. After `--all` or `--out` over line rows the `apps:` line is the number of apps of the rows of the walk. `--context` with `--path` against a server without both is refused once for both flags.
- `SKILL.md`: the code search procedure for agents has the steps `--apps` for the app list, `--package PKG --context 5 --path GLOB` to read the matches, and `citt code-file PACKAGE PATH` for the whole file.

## 2.53.0

- `citt code-search` for agents (TASK-1502, epic TASK-1500). Every answer ends with labelled lines: `matches: N (exact)` or `matches: at least N`, `apps:` in the same two forms, `shown: N rows`, `complete: yes` or `complete: no (<reason>)`, and `next:` with the full command to run next (query, flags and the `--cursor` value), sometimes followed by `or:` with a second choice. The reasons are in plain words: the time limit, the row cap of one search, a part of the index that did not answer, a stop at `--max-rows`, a refused page. Exit 0 is a complete answer or a page whose `next:` command fetches the next page; an incomplete answer that no cursor continues is exit 12 with its `next:` line (before: exit 0). A search with no row prints its cause above the footer.
- `--apps` prints one row per app (`PACKAGE  MATCHES  SAMPLE PATH:LINE  SNIPPET`); it works with `--all`, `--out` (CSV header `package,matches,builds,corpus,path,line,text`) and `--json`.
- `--count` prints the verified numbers of matching lines and apps with the `complete:` line, and the candidate files as a separate line, `scan cost: about N candidate files`; a partial count prints `at least N` (before: `Could not estimate`).
- `--all` and `--out` follow the pages to the end with a progress line per page on stderr; `--max-rows N` replaces the 50-page stop; its default is the number of rows one search collects. Rows fetched before a refused page are printed or written, and the `next:` command continues at that page. An existing `--out` file keeps its content until the first page is fetched.
- `--json` prints the service body with its `complete`, `counts`, `window` and `resume_cursor` fields; `--all --json` prints the body of the last page with the rows of every page (before: a rebuilt document with four fields).
- After a stop at the time limit the `next:` line says to narrow the search (`--package`, `--corpus`, a more specific query), and the `or:` line is the same command with a longer time limit; the `or:` line is absent when a longer time limit does not change the answer.
- When the results change while `--all` or `--out` reads the pages, the walk starts again from the first page once; after a second change the rows of the current walk are printed or written with `complete: no (the results changed while paging)` and exit 12. A single `--cursor` page of changed results prints the command without `--cursor` (exit 7).
- The two limits on searches at once (per account and for the service, and searches with a time limit above 30 s) are refused with the wait in seconds and a next action (exit 6), like too many searches in a short time; `--all` and `--out` wait and continue with the same page, up to 3 waits per page, and keep the rows fetched when the waits are used up.
- Arguments: `--time-limit-ms` takes 1000 or more, up to 120000; the service may apply a lower limit; `--corpus` is checked against the nine corpus names before the request; `--` ends the options, so a query may start with `-`; an option given as the value of another option is a usage error.
- Texts: the footer and the help name no engine word; help and the reference name the `code_search` entitlement, and an account without it gets the reason and a next action (exit 3). The reference and `SKILL.md` have a code search procedure for agents.
- The same footer and exit codes are printed against a service version without the new fields, read through its older fields; there `--count` prints `matches: unknown` with the scan cost, and `--apps` prints that the server does not offer it yet (exit 10).

A package id and a Play link without a referrer start a run as before. The parameter name is `referrer` in lower case; a link with `Referrer=` has no install referrer. An app that is preinstalled on the lab phone has no such run.

## 2.0.0

- Rewritten for the CanITrustThat research API (`/api/research/v1`): scans by a versioned rule pack with findings, evidence, facts and a compliance status per regime.
- Every account can use the plugin. A Pay as you go account scans one Android app at a time (`citt submit PACKAGE`) and asks questions about an app (`citt prompt`); projects, CSV submits, findings across a project, scrutiny, exports, owners and iOS scans are on the Researcher, Deep Researcher and Custom plans.
- New commands: `projects`, `status`, `apps`, `app`, `findings`, `scrutinize`, `prompt`, `export-results`, `export-sources`, `owners`, `usage`.
- Removed: the 0.4 commands `search`, `results`, `claim`, `mine`, `report`, `scan`, `result` and `rescan`, whose routes were retired in October 2026. A question about one app is `citt prompt`; a rescan is `citt submit --rescan` in a project.
- Codex: the same repository is a Codex plugin marketplace (`codex plugin marketplace add CanITrustThat/citt-plugin`).
- The token stored by 0.4 is used as is.
