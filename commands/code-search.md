---
description: Search the decompiled app corpus by literal string or regular expression
argument-hint: QUERY [--regex|--literal] [--case-sensitive] [--corpus C] [--package PKG] [--build-id ID] [--path GLOB] [--context N] [--apps] [--count] [--limit N] [--cursor C] [--all] [--out FILE.csv] [--append] [--max-rows N] [--max-empty-pages N] [--time-limit-ms MS] [--json]
allowed-tools: Bash(${CLAUDE_PLUGIN_ROOT}/skills/citt/scripts/citt:*), Read
---

Run `${CLAUDE_PLUGIN_ROOT}/skills/citt/scripts/citt code-search $ARGUMENTS` and relay the result.

Search the decompiled code of every indexed app build for a string (`--literal`, the default) or a regular expression (`--regex`); the match ignores case by default (`caramelads` also matches `s4eCaramelAds`), so search that way first; `--case-sensitive` narrows a search that stops at the time limit and then misses the other casings of the string. Narrow with `--corpus` (one of `java resource manifest string asset native js hermes dart`), `--package` or `--build-id` (each repeatable), and with `--path GLOB` (repeatable, at most 16): a file is kept when its path matches one glob; `*` is any run of characters except `/`, `**` any run, `?` one character except `/`; a glob with no `/` is compared with the file name. `--context N` (0 to 10) also prints N lines before and after each matching line in grep style: `PACKAGE  PATH:LINE: TEXT` for the match, `PACKAGE  PATH-LINE- TEXT` for a context line, `--` between two matches; with `--out` the CSV gets the columns `context_before` and `context_after`. To read a whole file of a row, run `citt code-file PACKAGE PATH`. A query that starts with `-` goes after `--`. `--apps` prints one row per app (`PACKAGE  MATCHES  SAMPLE PATH:LINE  SNIPPET`): the answer to "which apps contain this". `--count` prints the verified number of matching lines and apps with no rows, and a `scan cost: about N candidate files` line, which is the number of files read and never a result count. `--limit` is 1 to 200 rows per page; `--cursor C` fetches the page at `C`; `--all` follows every page to the end with no `--cursor` value copied by hand, to `--max-rows N` (default 10000; 0 is no bound) or to `--max-empty-pages N` pages in a row with no row (default 50; 0 is no bound), with a progress line per page on stderr; `--out FILE.csv` writes every fetched row to a CSV (`package,corpus,path,line,text`, with `--apps` `package,matches,builds,corpus,path,line,text,builds_exact`, where `builds_exact` `false` marks a builds number that is a lower bound) and implies `--all`; `--append` adds the rows to the end of the file under its header line; without it `--out` replaces an existing file, also when the search has no row. `--time-limit-ms` is the time limit of one request: 30000 without the flag (a page, `--count`, and each request of `--all` and `--out`), 1000 or more, up to 120000; the service may apply a lower limit (its largest is 90000 by default). The limit is a ceiling: a search ends as soon as its files are read.

Every answer ends with labelled lines: `matches: N (exact)`, `matches: at least N` or `matches: none found so far` (the search stopped before it reached a match; `0 (exact)` means absent), with `case-sensitive` in the brackets under `--case-sensitive`; `apps:` in the same three forms; `shown: N rows` (or the written line of `--out`); `complete: yes` or `complete: no (<reason>)`; `next:` with the full command to run next (the `--cursor` value included); `hint:` with a sentence. In the footer a line that starts with `next:` is a command to run as printed, and a line that starts with `hint:` is a sentence (how to narrow, or what to check). Relay the `complete:` line with every count: a number is exact only with `complete: yes`, and `at least N` is a lower bound. Exit 0 is a complete answer or a page whose `next:` command fetches the next page; such a page can print `complete: no (more rows follow on the next page)`, and `--all` or `--out` follows the pages to `complete: yes`. A page can have no row and a `next:` command: with `--apps` the rows are listed by the call that ends the scan, and a call before it prints the numbers found so far as `at least N`; run the `next:` line, or use `--all`. A walk stops after 3 requests in a row with no row, the same cursor and the same numbers (4 with `--apps`; exit 12), after `--max-empty-pages` pages in a row with no row, or at `--max-rows` (both exit 0, with the `next:` command of that page); after the 3 requests with no change (4 with `--apps`) there is no `next:` line, since a repeat would end the same way. Exit 12 is an incomplete answer that no cursor continues (the time limit, the row cap of one search, a part of the index that did not answer): run the `next:` line as printed when there is one (the same search again, or the search with the longest time limit of the service), and narrow as the `hint:` line says: after a stop at the time limit it has the number of files the query has to read when the service sent it (a longer or rarer string reads fewer; `--package` or `--corpus` limit it). A search with no row prints its cause above the footer; under `--package`, `--build-id`, `--corpus` or `--path` the cause is no match in the apps and paths of this search, and the hint names the flags of the command that can be dropped. Rows fetched before a refused page are printed or written, and the `next:` command continues at that page (for `--out FILE.csv`, into `FILE.next.csv`; the `next:` command of a run into `FILE.next.csv` adds to that file with `--append`, so the rows of every continuation are in one file). When the results change while `--all` or `--out` reads the pages (another search of the same query ran), the walk starts again from the first page once; after a second change the rows of the current walk are printed or written with `complete: no (the results changed while paging)` and exit 12, and a single `--cursor` page of changed results prints the command without `--cursor` (exit 7). Too many searches from one account in a short time, or the most searches at once in progress, are refused with the wait in seconds and a next action (exit 6); `--all` and `--out` wait that time and continue with the same page, up to 3 waits per page. In the CSV, a cell beginning with `=`, `+`, `@` or `-` is prefixed with a single quote (a spreadsheet formula guard). `--json` prints the service body (`complete`, `counts`, `window`, the cursor of the next page); with `--all`, the body of the last page with the rows of every page. A server without context lines or the path filter prints that and the command without the flag (without both when both were given; exit 8). The account needs the `code_search` entitlement; without it the command prints the reason and a next action (exit 3). Never read or print the token.
